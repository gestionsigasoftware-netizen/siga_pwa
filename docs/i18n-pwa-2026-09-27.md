# i18n en la PWA (Fase 3) — 2026-09-27

## Contexto

Tras cerrar la traduccion de las 47 pantallas del proyecto web
(`siga-nacional`) a espanol/ingles/portugues, quedaba pendiente la
Fase 3: aplicar el mismo idioma a la PWA de captura movil
(`siga-pwa-nacional`), un proyecto aparte con su propio repo.

## Alcance real (mas chico que el web)

La PWA tiene 8 pantallas reales (~940 lineas en total) mas 2 wrappers
triviales sin texto (`NotFound.jsx` es la unica realmente pequena, y
`Skeleton.jsx`/`ProtectedRoute.jsx` no tienen texto visible). No
existia ninguna infraestructura de i18n de partida (sin `i18next`
instalado, sin selector de idioma en ninguna pantalla).

## Decision de UX (elegida por el usuario)

Se evaluaron 3 opciones para el selector de idioma:
1. Icono en Login + Home (elegida) -- accesible antes y despues de
   iniciar sesion, sin agregar pantallas nuevas.
2. Solo en Login -- descartada, un usuario logueado por meses no
   podria cambiarlo nunca.
3. Nueva pantalla de Ajustes -- descartada, la PWA no tiene ninguna
   pantalla de configuracion y agregar una solo para esto le suma
   complejidad a un flujo pensado para ser minimo (2 toques).

**Modo oscuro**: se confirmo que la PWA NO lo tiene (colores fijos en
`tailwind.config.js`, `color-scheme: light` forzado explicito en
`index.css`). Queda fuera de alcance de este cambio.

## Cambios

- Instalado `i18next` + `react-i18next` + `i18next-browser-languagedetector`
  (mismas versiones que el proyecto web).
- `src/i18n/index.js` -- mismo patron exacto del web: recursos
  es/en/pt, deteccion via `localStorage` con la clave `sigap:idioma`
  (aislada por origen, no colisiona con la del web aunque comparta
  nombre).
- `src/i18n/locales/{es,en,pt}.json` -- namespaces `common` (compartido:
  aria-labels repetidos, "(opcional)", mensajes de error/exito
  identicos entre las 4 pantallas de captura), `login`, `home`,
  `estadisticas`, `capturaActividad`, `capturaCarcelaria`,
  `capturaAmigo`, `capturaInterno`, `notFound`. 202 llaves en total,
  0 faltantes verificado con script en los 3 idiomas.
- `src/components/LanguageSwitcher.jsx` -- puerto directo del
  componente ya usado en el web (mismo patron ES/EN/PT en pildora),
  adaptado a los tokens de color propios de la PWA, con variante
  `dark` para el encabezado oscuro de Login.
- Agregado a `Login.jsx` (encabezado oscuro) y `Home.jsx` (encabezado
  claro, junto al indicador de conexion).
- **Patron "valor conocido, no de BD" reutilizado**: `MODULOS_CONOCIDOS`
  en `src/lib/modulos.js` (el catalogo fijo Ujieres/Evangelismo/Mision
  Juvenil/Obra Carcelaria que arma los botones de Home) se dejo
  intacto -- en `Home.jsx` se reemplazo `modulo.nombre` por
  `t('common.modulos.' + modulo.id)` para la etiqueta visible, sin
  tocar el campo `nombre`/`match` que usa la logica de emparejamiento.
  Distinto de `modulo.nombre_modulo` (el nombre REAL configurado por
  cada congregacion en la base de datos, ej. "Ujieres Templo Central"),
  que se dejo sin tocar en las 4 pantallas de captura por ser dato de
  usuario, no texto de interfaz -- mismo criterio ya aplicado en el
  proyecto web para `CARGO_OPTIONS`/valores de catalogo.
- **Bug de fechas corregido de una vez, no arrastrado**: `Estadisticas.jsx`
  formateaba fechas con `toLocaleDateString('es-CO', ...)` fijo (mismo
  patron que quedo pendiente en `ReportesOptimizado.jsx` del web,
  documentado ahi como "hallazgo transversal, pendiente de pasada
  dedicada"). Aqui, al construir el namespace desde cero, se corrigio
  de inmediato con un locale dinamico
  (`i18n.language === 'en' ? 'en-US' : i18n.language === 'pt' ? 'pt-BR' : 'es-CO'`),
  igual que el patron ya usado en varias pantallas del web
  (ImpactoMisionero, RutaFormacion, EstacionRefam, PastoralDistrital).

## Verificacion

1. Script de llaves: 202 llaves usadas en el codigo, 0 faltantes en
   es/en/pt.
2. `npm run build` real sin errores.
3. Playwright real contra `npm run dev` (puerto 5174, el 5173 estaba
   ocupado por el proyecto web): pantalla de Login en los 3 idiomas
   antes de iniciar sesion; login real con la cuenta de prueba
   (`pueba691@gmail.com`, rol `local`, mismo backend Supabase que el
   web); Home completo en ingles (encabezado, tarjetas de modulos,
   boton "Sign out"); clic real en el selector de idioma (ES/EN/PT)
   confirmando el cambio en vivo sin recargar; entrada real a un
   formulario de captura (`/captura/:id`) en portugues mostrando datos
   reales de la congregacion de prueba (tipos de culto, lista de
   ujieres) -- cero errores de consola en todo el recorrido.
